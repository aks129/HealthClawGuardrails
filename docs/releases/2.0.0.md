# HealthClaw Guardrails 2.0.0 — the synthetic-beta release

2.0 is the release a beta tester can use on synthetic records. It is not the
end of the refactor. The ratchets that measure that work continue as 2.x,
and the numbers below say where each one stands.

The full change list is in [CHANGELOG.md](../../CHANGELOG.md). The definition
of done is in
[the playbook's §5](../2026-08-05-healthclaw-2.0-playbook.md#5-definition-of-done-for-20).

## What 2.0 is

- **Guardrails on by default.** Every record an agent reads is redacted
  before the model sees it. Every access writes an audit event with a
  PHI-free detail. Every tenant sees only its own records.
- **Writes need a step-up token.** A caller without one is refused, and the
  refusal states its reason.
- **Real-world actions wait for a person.** An agent can propose a call, a
  text or a form. Only an approval on a separate page runs it. That approval
  is bound to the payload the person was shown.
- **Grade A conformance** on the guardrail harness, held on every merge.
- **A hosted consumer app, CareAgents**, with passkey sign-in, synthetic
  sample records and self-serve account deletion.

## Not in 2.0

These are stated plainly so nobody has to find them in the code.

- **The direct FHIR write gate is a header.** Direct clinical writes still
  accept a client-supplied `X-Human-Confirmed` header. That is not a human
  gate. The action rail is the real gate. Tracked in
  [#214](https://github.com/aks129/HealthClawGuardrails/issues/214).
- **The MCP OAuth connector is off.** The authorization server and consent
  handoff are built, behind `MCP_OAUTH_ENABLED`. Production stays
  token-locked until the owner enables it
  ([#568](https://github.com/aks129/HealthClawGuardrails/issues/568),
  [runbook](../runbooks/mcp-connector-enablement.md)).
- **The Curatr fix rail is dark.** A data-quality fix can ride the action
  rail, behind `CURATR_FIX_RAIL_ENABLED`, which is unset. Tracked in
  [#413](https://github.com/aks129/HealthClawGuardrails/issues/413).
- **Real records are invite-only.** CareAgents opens real-record connections
  only where `CARE_REAL_RECORDS` allows them. The default is off.
- **No clinician has signed off yet.** The first clinician walkthrough is
  open as [#677](https://github.com/aks129/HealthClawGuardrails/issues/677).
- **The ratchets are not at zero.** These are the live pins in
  `tests/test_ratchets.py`:

| Ratchet | 2026-08-06 | 2.0.0 | Target |
|---|---|---|---|
| Post-commit audit call sites | 88 | 87 | 0 |
| Raw tenant-header reads | 55 | 24 | 0 |
| Direct step-up validation | 20 | 4 | 0 |
| Soft-delete-blind files | 12 | 8 | 0 |
| Imports out of `routes.py` | 4 | 4 | 1 |
| `routes.py` lines, a ceiling | 3,930 | 3,761 | shrinks |

Step-up sites without a nonce have no live pin yet. Contract ingest
(workstream C) has not started.

## Upgrading from 1.9.0

Flagged behaviour ships off. Run the Alembic migrations before the first
request. Then check `GET /r6/ops/preflight`, which reports the production
settings it checks. 2.0 adds one: a step-up nonce store shared across
workers (#212).
